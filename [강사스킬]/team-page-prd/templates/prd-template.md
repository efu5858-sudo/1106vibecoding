| 항목 | 내용 |

| 관련 문서 | logo-prompt.md, build-plan.md |

> PRD(Product Requirements Document)는 "무엇을, 누구를 위해, 왜 만드는지"를 모두가 같은 그림으로 보게 하는 문서입니다.

## 1. 배경 · 문제
- 지금 어떤 불편이 있는가 (예: "우리 팀에 무엇을 부탁할 수 있는지 몰라 엉뚱한 곳에 문의가 간다")
- 왜 지금 이 페이지가 필요한가

## 2. 목표와 성공 기준
| 목표 | 성공 기준 (측정 방법) |
|---|---|
| 처음 보는 사람이 우리 팀을 1분 안에 이해한다 | 신규 입사자 3명에게 보여 주고 "무슨 팀?"에 답할 수 있음 |
| 요청이 올바른 채널로 온다 | 오픈 후 한 달 동안 잘못 온 요청 수 감소 |

## 3. 대상 사용자
| 대상 | 궁금한 것 | 페이지가 줘야 할 답 | 기대 행동 |
|---|---|---|---|
| | | | |

**이번에 안 만드는 것 (Out of scope)**

## 9. 반응형 · 접근성
- 휴대폰(375px) ~ 데스크톱(1280px)에서 깨지지 않는다, 가로 스크롤 없음
- 카드: 데스크톱 N열 → 태블릿 2열 → 휴대폰 1열
- 휴대폰에서는 메뉴를 햄버거 버튼으로
- 글자와 배경의 대비가 충분하고, 이미지에는 대체 텍스트를 넣는다

## 10. 기술 조건
- `index.html` 파일 하나, 빌드 도구 없이 더블클릭으로 열림
- 외부 의존은 글꼴 CDN 정도로 최소화
