# 팀 홈페이지 PRD 제작기

수강생과 대화하면서 **우리 팀 소개 홈페이지**를 기획하고, 확인을 받은 뒤 실제로 만들어 주는 스킬입니다.

## 결과물 (순서대로)

| # | 파일 | 내용 |
|---|---|---|
| 1 | `prd.md` | 현업에서 쓰는 형식의 PRD |
| 2 | `logo-prompt.md` | ChatGPT(GPT 이미지)에 붙여 넣을 로고 프롬프트 |
| 3 | `build-plan.md` | 홈페이지 제작 계획서 |
| 4 | `index.html` + `images/` | **"만들까요?"에 사용자가 그렇다고 한 뒤에만** 만든다 |

모든 파일은 작업 폴더 아래 `team-page/` 폴더에 둡니다. 이미 그 폴더가 있으면 `<팀영문이름>-page/`를 씁니다. 덮어쓰기 전에는 꼭 묻습니다.

## 대화 원칙

- **한 번에 한 라운드**, 라운드당 질문은 2~3개. 질문을 한꺼번에 쏟아내지 않는다.
- 질문마다 **예시 답**을 붙인다. 수강생 대부분은 처음이라 빈칸에서 막힌다.
- 답이 짧거나 "모르겠어요"면 **후보 2~3개를 제안**하고 고르게 한다. 대신 정해 버리지 않는다.
- 답을 들으면 한 줄로 되짚는다: "정리하면 ___ 팀이네요. 맞나요?"
- 개인정보 · 회사 정보는 넣지 않는다 (수업 저장소 규칙과 같음). 실명 대신 닉네임, 회사 이름 · 부서 · 사내 시스템 주소 · 고객 정보 · 연락처 · 비밀번호 · API 키는 쓰지 않는다. 연습은 **가상의 팀**으로 하고, 문의 칸은 예시 값(`team@example.com`, `#채널명`)을 쓴다. 사용자가 실제 회사 이름을 말하면 가상 이름으로 바꾸자고 제안한다.
- 쉬운 말을 쓴다. PRD·IA 같은 용어는 처음 나올 때 한 줄로 풀어 준다.

## 1단계 · 인터뷰 (4라운드)

질문 원문과 예시 답은 `references/question-bank.md`에 있다. 그대로 읽지 말고 앞선 답에 맞춰 다듬어 묻는다.

1. **우리 팀은 어떤 팀인가요?** — 팀 이름, 한 줄 정의, 소속·규모
2. **누가 보나요?** — 주 방문자, 그 사람이 보고 나서 했으면 하는 행동
3. **홈페이지에 어떤 내용을 넣고 싶으신가요?** — 메뉴 고르기, 업무 카드 내용, 아직 없는 칸("준비 중" 처리)
4. **어떤 분위기였으면 하나요?** — 메인 색, 느낌 3단어, 참고 사이트·이미지, 로고 유무

라운드 4가 끝나면 아래 요약을 보여 주고 고칠 곳이 있는지 묻는다.

```
📋 정리해 볼게요
- 팀: ___ (한 줄: ___)
- 보는 사람: ___ → 보고 나서 ___ 했으면
- 메뉴: ___
- 화면 순서: ___ → ___ → ___
- 분위기: ___색, ___ / ___ / ___
- 로고: 있음 / 없음(만들 예정)   참고 이미지: 있음 / 없음
```

## 2단계 · PRD 작성 → `prd.md`

`templates/prd-template.md`의 구조를 따른다. 인터뷰에서 안 나온 칸은 비워 두지 말고 합리적으로 채운 뒤 `(가정)` 표시를 단다. 마지막 "열린 질문"에 확인이 필요한 것을 모은다.

## 3단계 · 로고 프롬프트 → `logo-prompt.md`

`templates/logo-prompt-template.md`로 만든다. 교안의 기본 형태를 지킨다.

```
[팀 이름] 팀의 로고를 만들어 줘.
[색] 계열, 단순한 아이콘 + 팀 이름,
흰 배경, 정사각형.
```

여기에 팀 성격에서 뽑은 아이콘 아이디어 2~3개와 다시 뽑을 때 쓸 수정 문장을 덧붙인다. 그리고 이렇게 안내한다.

> ChatGPT에 이 프롬프트를 붙여 넣어 로고를 만든 뒤, 마음에 드는 이미지를 **여기에 올려 주세요.** `images/logo.png`로 저장해서 쓸게요. 참고하고 싶은 사이트 화면이 있으면 그것도 같이 주세요(`images/reference.png`).

이미 로고가 있다고 했으면 이 단계는 짧게 넘어가고 파일만 받는다.

## 4단계 · 제작 계획서 → `build-plan.md`

`templates/build-plan-template.md`로 만든다. 무엇을, 어떤 순서로, 어떻게 확인할지 적는다. 준비물 체크(로고·참고 이미지)를 꼭 넣는다.

## 5단계 · "만들까요?"

세 파일 경로를 알려 준 뒤 **반드시 멈추고** 묻는다. 사용자 답 없이 만들지 않는다.

> 계획서까지 나왔어요. 이대로 홈페이지를 만들까요?
> 1. 지금 만들기 — 로고가 없으면 임시 글자 로고로 먼저 만들고 나중에 바꿀 수 있어요
> 2. 로고·참고 이미지 넣고 만들기 — 파일을 올려 주시면 그걸로 만들게요
> 3. 계획 고치기 — 바꿀 곳을 말해 주세요

이 확인 단계가 있는 이유: 수강생이 계획을 읽고 직접 고치는 경험을 하게 하고, 로고·참고 이미지를 받을 자연스러운 시점이 되기 때문이다.

## 6단계 · 홈페이지 만들기 → `index.html`

교안의 제작 프롬프트를 그대로 수행한다고 생각한다.

```
team-page 폴더의 prd.md를 읽고 팀 소개 페이지를 만들어 줘.
- 파일 이름은 index.html
- 로고는 images/logo.png
- images/reference.png의 분위기와 배치를 참고
- 휴대폰에서도 보기 좋게
- "우리가 만든 도구" 칸은 "준비 중" 카드로
```

만드는 규칙:
- **파일 하나**(`index.html`), CSS·JS는 안에 넣는다. 빌드 도구 없음. 글꼴은 Pretendard CDN 정도만.
- 색은 `:root` 변수로 모아 PRD의 색을 그대로 쓴다.
- 상단 고정 메뉴 → 각 섹션으로 부드럽게 이동. 640px 아래에서는 햄버거 메뉴.
- 카드 그리드: 데스크톱 3~4열 → 태블릿 2열 → 휴대폰 1열. 휴대폰 좌우 여백은 16px, 가로 스크롤이 없어야 한다.
- 아직 없는 칸은 점선 테두리 + "준비 중" 배지 카드.
- `images/logo.png`가 없으면 팀 이름 첫 글자를 넣은 인라인 SVG로 임시 로고를 만들고, 나중에 파일만 넣으면 바뀐다고 알려 준다.
- `images/reference.png`가 있으면 열어 보고 색·여백·배치를 참고한다. 없으면 PRD만 따른다고 말한다.

다 만들면 확인한다.
- 브라우저 미리보기가 되면 데스크톱과 휴대폰 폭(375px)에서 열어 보고, 가로 스크롤이 없는지와 메뉴가 동작하는지 본다.
- 미리보기가 안 되는 환경이면 `index.html`을 더블클릭해서 열어 보라고 안내한다.

## 마무리 안내

- 만든 파일 목록과 각각 무엇인지 한 줄씩
- 바꾸고 싶을 때 쓰는 문장 예시: "업무 카드를 하나 더 넣어 줘", "색을 초록 계열로 바꿔 줘", "멤버 소개 칸을 추가해 줘"
- 다음 단계 제안: 실제 도구가 생기면 "준비 중" 카드를 바꾸기, 팀원에게 링크 공유하기
