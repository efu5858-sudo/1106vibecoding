# 나만의 업무 OS 만들기 (웹페이지형)

**업무 OS** = 매일 아침 브라우저에서 여는 한 장짜리 페이지. 내가 반복하는 일을 한곳에 모아서 덜 찾고, 덜 베끼고, 덜 까먹게 해 준다.

## 결과물 (순서대로)

| # | 파일 | 내용 |
|---|---|---|
| 1 | `os-prd.md` | 업무 OS 기획서 (현업 PRD 형식) |
| 2 | `os-build-plan.md` | 제작 계획서 |
| 3 | `index.html` | **"만들까요?"에 그렇다고 한 뒤에만** 만든다 |

폴더는 `my-os/`를 쓰고, 이미 있으면 `<닉네임>-os/`를 쓴다. 덮어쓰기 전에는 묻는다.

## 대화 원칙

- **한 번에 한 라운드**, 질문은 2~3개, 예시 답을 함께 준다.
- 답을 들으면 **가설을 던져 확인**한다: "들어 보니 진짜 비용은 ___ 같은데, 맞나요?" 사용자가 스스로 몰랐던 핵심을 찾게 하는 것이 이 스킬의 가치다.
- 막히면 비슷한 직무의 예시를 2~3개 보여 주고 고르게 한다.
- **처음 버전은 작게.** 화면 모듈은 최대 3개. 나머지는 "다음에 붙일 것"으로 남긴다.
- 개인정보 · 회사 정보는 넣지 않는다. 실명 대신 닉네임, 회사 이름 · 고객 정보 · 사내 시스템 주소 · 비밀번호 · API 키는 쓰지 않는다. 화면에 들어갈 예시 데이터는 가짜로 만든다.

## 1단계 · 인터뷰 (4라운드)

질문 원문과 예시 답은 `references/question-bank.md`에 있다.

1. **일의 풍경** — 어떤 일을 하는지, 하루·한 주에 시간을 가장 많이 쓰는 일 3가지
2. **반복과 불편** ⭐ — "업무에서 가장 반복되고 불편한 건 무엇인가요?" 얼마나 자주, 몇 분, 지금은 어떤 도구로 하는지. 어느 부분이 진짜 비용인지 한 번 더 파고든다.
3. **이상적인 아침** — "출근해서 이 페이지를 열면 무엇이 이미 보이면 좋겠어요?"
4. **기록할 것** — 무엇을 적고 관리하는지(항목·칸), 혼자 쓰는지 팀이 쓰는지, 휴대폰에서도 보는지

라운드 2가 끝나면 통점을 한 문장으로 되짚는다.

```
🎯 내 업무 OS가 풀 문제
"나는 [언제] [무슨 일]을 [얼마나 자주] 하는데, [어느 부분]이 가장 번거롭다."
```

## 2단계 · 화면 모듈 고르기

`references/module-catalog.md`에서 통점에 맞는 모듈을 **2~3개 추천**하고 이유를 한 줄씩 붙인다. 사용자가 고르게 한다. 그리고 화면 배치를 글 그림으로 보여 준다.

```
┌──────────── 오늘 · 11월 6일 (목) ────────────┐
│ [모듈 A: 오늘 할 일]   │ [모듈 B: 숫자 요약]  │
├────────────────────────┴─────────────────────┤
│ [모듈 C: 기록 표]                             │
└───────────────────────────────────────────────┘
```

## 3단계 · 기획서 → `os-prd.md`

`templates/os-prd-template.md`를 따른다. 인터뷰에서 안 나온 칸은 합리적으로 채우고 `(가정)`을 단다. 데이터 칸(필드) 표를 꼭 채운다. 만들 때 이 표가 그대로 쓰인다.

## 4단계 · 제작 계획서 → `os-build-plan.md`

`templates/os-build-plan-template.md`를 따른다. 모듈별 구현 순서, 데이터 저장 방식, 확인 방법을 적는다.

## 5단계 · "만들까요?"

두 파일 경로를 알려 주고 **반드시 멈추고** 묻는다.

> 기획서와 계획서가 나왔어요. 이대로 업무 OS를 만들까요?
> 1. 지금 만들기
> 2. 모듈 바꾸고 만들기 — 빼거나 더할 모듈을 말해 주세요
> 3. 기획 고치기

## 6단계 · 만들기 → `index.html`

만드는 규칙:
- **파일 하나**(`index.html`), CSS · JS 모두 안에 넣는다. 빌드 도구 · 서버 · 로그인 없음. 더블클릭으로 열린다.
- **저장은 브라우저 `localStorage`**. 키 이름은 `myos:<모듈>` 형식. 읽고 쓸 때 `try/catch`로 감싸서 저장이 막혀도 화면은 뜨게 한다.
- **백업 · 복원 버튼**: 전체 데이터를 JSON 파일로 내려받기 / 파일에서 불러오기. 브라우저 기록을 지우면 데이터가 사라질 수 있다고 화면과 안내에 적는다.
- 처음 열었을 때 비어 있지 않게 **가짜 예시 데이터 3~5건**을 넣고, "예시 지우기" 버튼을 둔다.
- 맨 위에 오늘 날짜와 인사, 그 아래 고른 모듈. 데스크톱 2열 → 휴대폰 1열. 휴대폰 좌우 여백 16px, 가로 스크롤 없음.
- 색은 `:root` 변수로 모은다. 사용자가 분위기를 말하지 않았으면 차분한 남색 계열로 하고 그렇다고 말한다.
- 외부 서비스로 데이터를 보내지 않는다.

다 만들면 확인한다.
- 미리보기가 되면: 항목 추가 → 새로고침 → 그대로 남는지, 백업 파일이 받아지는지, 375px 폭에서 깨지지 않는지 본다.
- 미리보기가 안 되면: `index.html`을 더블클릭해서 위 세 가지를 직접 해 보라고 안내한다.

## 마무리 안내

- 만든 파일과 쓰는 법 3줄 (열기 → 입력 → 백업)
- 브라우저 즐겨찾기에 추가하거나 시작 페이지로 두라고 권한다.
- 다음에 붙일 것 1~2개를 문장으로 제안: "주간 요약 칸을 추가해 줘", "자주 쓰는 문구 복사 칸을 넣어 줘"
- 이 OS를 팀과 같이 쓰고 싶다면 그건 서버나 공유 저장소가 필요한 다음 단계라고 알려 준다.
